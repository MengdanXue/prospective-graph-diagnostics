## 守时、防睡眠与暂停须先实际验收

执行前申请只作用于本任务生命周期的 `SystemRequired` 与 `ExecutionRequired` 电源请求；普通结束、正常暂停、紧急停止及异常退出都须清除请求并关闭句柄，不修改全局或永久电源策略，不申请保持显示器或 away mode。申请/释放状态和失败均记录。Windows 的这些请求不保证阻止用户主动睡眠，而且 Modern Standby 在电池供电时有额外限制，因此仍须监测挂起/恢复事件并保留终止规则。[Microsoft PowerSetRequest 说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-powersetrequest)

外部监护进程独立监督完整验收主体，避免数据哈希、邻接准备或摘要写入阻塞时间检查。正常轮询间隔固定 0.25 秒；相邻轮询超过 **5 秒**，或 UTC 墙钟与单调钟经过时间差超过 **2 秒**，停止派发并在操作系统恢复可执行后终止所属活动进程树，保存差额与实际超时。直接订阅挂起/恢复事件（事件代码 4、7、18），即使事件短于五秒也触发停止复核。计账取 `max(0, 墙钟经过时间, 单调钟经过时间)`，不将实际超时截断为名义上限，不自动唤醒继续。

这些是操作系统能执行监护程序时实施的边界，不是在系统挂起期间也能瞬间终止进程的物理保证。守时、事件捕获、部分申请失败的清理、所有退出路径释放、进程树终止和共享累计账本，都须先通过可控测试及获准后的实际运行验收。

最新暂停指令优先于历史草稿：**正常暂停**停止派发新模型，等待当前模型的全部四个原 trial 完成、完整记录原子保存并验证后退出。当前探针工作进程虽一次容纳七模型，也须在本模型 `trial_003` 后写入完整单位标记并检查暂停，不能继续开始下一模型。**紧急停止**则终止所属进程树并保存未完成尝试。正常暂停仍受资源及时间上限约束，不能以等待完成为由延长预算。

恢复只可只读跳过完整且验证通过的模型单位；未完整单位不声称具备 epoch/Adam 续训能力，需要在同一来源和累计预算下重新执行其全部四 trial。先验证已有记录和剩余额度，不自动恢复、不重置单位/批次累计。暂停导致资源验收不完整时，保留全部证据；不能把未完成范围称为通过。

## 执行顺序与控制文件

执行入口为[资源协调器](../scripts/accept_input_robustness_resources.py)，由外层监护进程启动隔离的阶段主体；直接运行内部工作进程不能代替有来源、授权和账本绑定的入口。每次尝试使用独立且尚不存在的输出目录，可靠性目录与完整资源目录分开，账本路径保持同一个。操作次序如下。

1. 保存新源码提交 SHA、全部可执行来源哈希、配置哈希、授权文件哈希、旧数据绑定哈希、环境/设备信息，以及同 SHA 的 CI 凭据。凭据须包含 `lightweight-verification`、`full-protocol-verification`、`manuscript-build` 三个任务的最终成功状态。确认工作区干净，再建立阶段清单和账本活动；任何校验失败不得派发探针。
2. 首先执行 `runtime_reliability_only`。使用真实的所属子进程和小型合成四次调参记录，检查正常暂停、紧急停止、工作进程超时、监护间隔异常，以及子进程退出后最后一个监护间隔异常。五个场景都须留下实际进程清理和预期失败/暂停证据。此步没有模型训练；原生电源申请、通知注册、释放和注销由外层监护覆盖。
3. 可靠性主体成功仅是候选结果；外层还须核对最终时钟、所属进程全部退出、电源/通知清理、来源未变及账本结账，形成有效完成凭据。只有该凭据通过独立校验，才可进入 `resource_acceptance_only`。可靠性失败、清理错误或账本待复核均停止，不启动完整探针。
4. 完整资源阶段只读校验前一步凭据，以其可信账本末端重新打开**原账本**，沿用已用时间和剩余额度。执行固定 44 个工作进程及全部复跑检查、投影和最终审计。预算不足即停止，不能重新建账本或借用正式训练/协调分项。

两个命令都指定 `--config`、`--binding`、`--data-root`、`--output-root`、`--ci-receipt` 和 `--budget-ledger`。配置为 `configs/input_robustness_11_v2.json`，绑定为原 `results/diagnostic/posthoc_input_robustness_11_v1/preflight/data_binding.json`。源码工作树之外的共享账本固定为 `work/input-robustness-budget-v2`；从本次 `work/input-robustness-11` 工作树执行时传入 `../input-robustness-budget-v2`。执行清单须记录这些参数解析后的绝对路径，输出放在工作树之外以便两次启动均能核对干净源码。

可靠性命令额外使用 `--reliability-only`，不提供 `--ledger-head-receipt`；账本须尚不存在。资源命令去掉 `--reliability-only`，并增加 `--ledger-head-receipt <可靠性输出目录>/closed_ledger_receipt.json`，其 `--budget-ledger` 与上一步相同。`--ci-receipt` 指向当前已提交推送 SHA 的保存凭据，不能用历史提案的 CI 文件替代。内部 `--body`、`--worker-id` 和合成场景选项不作为对外启动入口。

实际可靠性运行不主动让整台电脑进入睡眠。短于五秒的挂起/恢复回调、时钟分歧和清理错误可由注入测试验证；这与真实运行中成功申请/释放电源请求、注册/注销通知是不同证据，报告不得将注入事件写成已发生并捕获的真实整机睡眠。Windows 的直接通知支持挂起、自动恢复和用户恢复事件，不能仅根据一次长轮询推断全部短事件。[Microsoft 通知接口](https://learn.microsoft.com/en-us/windows/win32/api/powerbase/nf-powerbase-powerregistersuspendresumenotification)

控制文件只写入当前尝试的输出目录；保存请求时间、原因及来源，保留原文件。请求被接收后不能通过删除文件声称自动恢复。

通过同一协调器的 `--request-pause --output-root <当前输出目录>` 请求正常暂停，或通过 `--emergency-stop --output-root <当前输出目录>` 请求紧急停止；两项不能同时使用。这两个控制命令只记录请求，不启动新验收、不修改预算，也不表示所属进程已经退出。须继续读取监护结束记录和阶段凭据确认实际状态。

| 操作 | 当前输出目录中的请求 | 验收行为 |
|---|---|---|
| 正常暂停 | `control/pause_request.json` | 停止派发；已有模型继续到四份原 trial 都保存、核验并写入 `unit_completions/<model>.json`，随后退出。尚未开始模型时直接暂停。 |
| 紧急停止 | `control/emergency_stop.json` | 外层和工作进程监护停止所属活动进程树；保存已完成文件及未完成尝试，不补造完整单位标记。 |
| 预算、内存、磁盘、挂起/恢复或时钟异常 | 由监护记录触发，无需操作请求文件 | 依最先触发的边界停止并保留真实经过时间、超限量、进程退出与清理证据，等待复核。 |

运行返回成功、正常暂停、紧急停止或异常，都必须走独立的通知注销和电源释放路径；一个清理步骤失败不能跳过另一个。申请或记录失败时也须清理已经获得的资源。最终检查还应读取注销后的事件快照，避免漏掉最后一次轮询与注销之间抵达的挂起/恢复事件。`released=true` 只表示已无电源句柄，不能抵消曾发生的清理错误。外层自身被强制终止或掉电而缺少显式清理/结账凭据时，该次尝试保持未验收，不能据已有候选摘要报告通过。

## 可信完成凭据与中断复核

`preflight_summary.json`、`body_complete.json` 或 `reliability_body_result.json` 只记录主体候选结果；进程退出码也不是单独的通过依据。两阶段都由外层生成 `acceptance_completion.json` 与 `closed_ledger_receipt.json`，须对这两个文件和原共享账本一起调用独立完成校验，才构成阶段完成。`closed_ledger_receipt.json` 绑定完成文件的 SHA-256、已关闭活动及可信账本末端；任一文件缺失、状态不通过或哈希不符都不可报告通过。凭据须能核对以下信息。

| 凭据内容 | 独立校验要求 |
|---|---|
| 授权、来源与阶段 | 运行标识、阶段、输出目录、配置/授权/输入绑定哈希、源码 SHA、可执行文件哈希、环境和同 SHA CI 均一致。资源阶段同时绑定可靠性完成凭据的文件哈希。 |
| 主体证据 | 候选结果及文件清单哈希匹配；可靠性五场景完整，或资源阶段 44/1,232/616 范围完整且全部检查通过。验证评分、测试评分、正式记录始终为零。 |
| 最终监护与清理 | 包括最后监护间隔及最终事件快照；无未处理停止原因、无仍存活所属进程；两种电源请求曾成功申请并已释放，通知曾成功注册并已注销，清理错误列表为空。 |
| 累计预算 | 活动已关闭；全部阶段累计用量、剩余额度和实际超时均可重放；资源分项及 384 小时总额没有清零、漏账或自动转移。 |
| 可信账本末端 | 凭据在账本外保存事件序号/末端哈希与尾部结账时间增量，包含最后账本写入的计时结算。重新打开时使用完整可信末端，不自行从当前日志推导替代。 |

日志自身的哈希链不足以发现整个尾部被删去，因此重开账本必须与前一次独立保存的可信末端比对；尾部结账增量须先结算再开始新工作。中断后只读检查序号、链、写锁、开放活动和来源。残留写锁、未关闭活动、截断记录、来源漂移、缺少可信末端或待结账增量，均不得自动修补或重试。若进程实际退出时间无法证明，保守计入至检查时的经过时间，并明确计时不确定性；更换目录不改变这一规则。

正常暂停是保留完整单位的未完成阶段；紧急停止是保留未完整尝试的未完成阶段。后续恢复前需保存复核记录并验证剩余预算和同一来源，且只跳过已经完整核验的单位。本阶段的探针权重不会用于正式训练。

## 保守投影与通过标准

单条件、单模型完整四次调参的投影增加明确准备成本。令每个 trial 的单轮时间取两次复跑中较大的平均时间；每个数据集/条件取较大的变换时间、较大的工作进程非训练开销，以及 H2GCN 的较大邻接准备时间。非训练开销为 `max(0, 工作进程墙钟时间 - 该进程全部 28 个探针的训练步骤时间和)`。

`U = 2 × [500 × 四个 trial 单轮时间之和 + 变换时间 + 非训练开销 + H2GCN 邻接准备时间（仅 H2GCN）]`。

每个 U 与 28,800 秒比较；对全部 154 个数据集/条件/模型身份求和并乘十个种子，与 **1,368,000 秒**比较。这与原全量保守公式一致，但明确了单模型准备开销；不以两数据集提速比例降低估计。三步、种子 0 的估计不是保证上界，实际训练仍须持续检查。

只有完整 44/1,232/616 范围、全部数据/来源/数值/复跑检查、实际守时和电源/暂停清理、内存资源及保守投影都通过，才能报告资源验收通过。缺项、异常、超限或来源变化均停止且保留失败；不按新分数改种子、数据集、模型、网格、条件或预算。
