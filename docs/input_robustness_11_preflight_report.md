## 时长瓶颈与证据边界

执行设备在预检前固定：H2GCN 在所有数据集、两种条件均用 CPU，其余六种模型使用 CUDA。原因是本地 H2GCN 所用 CUDA 稀疏矩阵乘法路径缺少严格确定性调度保证。原模型实现保持不变；这不是按表现换设备或增加输入条件。每次运行一个工作进程，Torch CPU/interop 线程为 4/1，启用严格确定性，禁止静默回退。

本次只测种子 0、每个设置三个训练步骤、两个全新进程复跑。整体时长按冻结公式，将各设置较慢复跑的平均单轮时间外推至 500 轮、十个种子，加入初始化等开销，再乘两倍余量。仅 H2GCN CPU 训练项的外推约为 **10.374 天，占总估计约 80.35%**，是主要瓶颈。

**12.910 天是预算判定用的保守估计，不是实际跑了十三天，也不是对最终耗时的保证上界。**短程复跑同样不能证明其余种子、全部轮次或不同硬件环境必定逐位一致；正式阶段仍须持续执行数值、确定性和资源检查。当前零评分记录不能用于准确率、遗憾损失或校准分析。

## 失败尝试保留、测试与同步

首轮 v1 保留了三个任务、84 个短程探针及人工停止记录。Windows 虚拟环境启动器派生实际计算子进程，首版协调器误将约 5 MB 的启动器内存当作工作进程内存，而实际子进程约为 1.9 GB。发现后仅终止本次协调器拥有的进程树。v1 不用于内存验收，也不混入 v2。其保留归档为 **625,903 字节**，SHA-256 为 `8b36457f49837c16b6c7ccf689d6f60a583a0a84ff2e430401b1141fb2e766dd`。

修复改为监测整个所属进程树及 Windows 内存峰值，并完整终止所属子进程。修复后使用全新 v2 目录，执行源码固定为 `d5427952a2e5ec915b3a183b23b4fb2b9dfcee13`。本地 **237 项测试通过，71.786 秒**。首个设计提交 `602b2f0` 与修复提交 `d542795` 均已同步远程；对应 CI [34767772798](https://github.com/MengdanXue/prospective-graph-diagnostics/actions/runs/34767772798) 和 [34768554546](https://github.com/MengdanXue/prospective-graph-diagnostics/actions/runs/34768554546) 的三个任务均成功。上述 CI 对应预检前的代码提交，CI 成功与本机预算门槛未通过分别报告。验收材料定稿时新增五项证据完整性检查，本地完整套件 **242/242 通过，耗时 66.727 秒**；验收提交的远程 CI 另行核对，不沿用此前提交的成功状态。

## 复现本阶段

以下为复跑说明，不是本报告自动启动的命令。使用依赖已安装的独立干净检出；为复现本次测量，源码应为上文 `d5427952a2e5ec915b3a183b23b4fb2b9dfcee13`。先核对提交和工作树，预检协调器也会拒绝未提交源码并持续核对源文件哈希：

```text
git rev-parse HEAD
git status --porcelain
```

将 `DATA_ROOT` 换为新数据目录，`RELEASE_ROOT` 换为已校验原 v0.1.0 发布归档并解压后的根目录（含 `MANIFEST.json` 和 `prospective`），`NEW_BINDING_JSON` 换为不存在的绑定输出文件。以下正式入口获取原版本数据、绑定全部切分，并补齐全部二跳诊断与拟合统计核验，不需要另行调用内部补全函数：

```text
python scripts/input_robustness_data.py --data-root DATA_ROOT --release-root RELEASE_ROOT --binding-output NEW_BINDING_JSON --acquire
```

若从已有且已绑定的数据目录恢复核验，可加 `--resume`，但最终绑定输出仍须使用新文件名；不得覆盖旧尝试。数据绑定通过后，将 `NEW_PREFLIGHT_OUTPUT` 换为全新、独立的预检输出目录：

```text
python scripts/preflight_input_robustness_11.py --config configs/input_robustness_11_v1.json --binding NEW_BINDING_JSON --data-root DATA_ROOT --output-root NEW_PREFLIGHT_OUTPUT
```

该命令只执行预检，输出目录必须不存在。本次因预算门槛未通过，协调器在保存完整摘要和清单后以退出码 2 结束；退出码不能被忽略而直接启动正式训练。所有路径占位符均须由复现者替换；不要将生成文件写进需要保持干净的检出目录。

## 下一阶段与仍未回答的问题

下一阶段先根据不涉及新验证或测试分数的证据，解决 **H2GCN CPU 执行效率、可用算力及时间预算方案**，明确所需修改的范围、等价性、资源上限和复检方法。若需调整预算，应说明算力与时间安排、停止及恢复规则；保留全部模型、数据集、种子和输入条件。任何执行或预算修订都应先形成可审查方案、测试、提交同步和实际 CI/资源验收记录。

资源方案得到验收后，才推进正式记录层与分析适配层，并以新的已提交启动记录绑定全部门槛；当前配置的 `formal_training_enabled=false` 保持有效。正式新记录需重新计算九种策略、主要选型损失、63 个图模型组合、等调参预算与固定敏感性、逐数据集留一校准，并分别报告结论保持、改变与未解决部分。
