# H2GCN CPU 执行成本：一轮固定性能诊断

设计日期：2026-09-14。[配置](../configs/h2gcn_performance_diagnostic_v1.json)标识为 `h2gcn_cpu_performance_v1`，阶段为 `performance_diagnostic_only`。本轮依据已完成的[资源预检](input_robustness_11_preflight_report.md)，仅诊断 H2GCN 执行成本，形成执行建议及需要用户确认的完整预算方案。

原[11 数据集方案](input_robustness_11_plan.md)的 11 数据集、两种输入、七种模型、十个种子、四次调参、正式预算和关闭的启动开关全部保留。`8847de6`、v1 停止尝试及 v2 预检记录不覆盖。本轮是后验性能诊断，不产生验证或测试评分、正式模型记录，也不回答模型准确率、选型损失、组合反转或校准结论是否保持。

## 固定瓶颈样例与规模

样例只根据 v2 [资源摘要](../results/diagnostic/posthoc_input_robustness_11_v1/preflight/resource_profile.json)的执行时间选择，原摘要 SHA-256 为 `31168a93a594f521269bd88aa93e29600394fd3987a62d0e22dcacb1f97a13f4`。按每个数据集所有 H2GCN 模型/调参/条件单元的 `measured_seconds_per_epoch` 求和，取最高两个；并列时数据集名称升序。排名前两项为 Squirrel（39.149970 秒）和 Actor（13.518469 秒）；Coauthor-CS（13.467121 秒）为第三，不因本轮新结果替换样例。

该排序仅描述 v2 的三个步骤探针，Actor 与 Coauthor-CS 很接近；它不确定一般运行中的最坏数据集顺序，也不说明邻接复制就是耗时根因。

在选定数据集内部，按同一原 trial 在两种条件下的单轮时间求和，取最大者；并列时取较小的原 trial 标识。两种条件使用同一个被选 trial。

| 数据集 | 原 trial | 学习率 / dropout | 两条件单轮时间和 |
|---|---|---|---:|
| Squirrel | `trial_000` | 0.01 / 0.5 | 9.992673 秒 |
| Actor | `trial_001` | 0.01 / 0.7 | 3.743477 秒 |

固定比较 `normalize_features` 与 `normalize_centered_scaled`；固定种子 0；CPU 线程数为 1、4、8，interop 线程为 1。每个设置包括下述两种 checkpoint 方式、两个全新进程复跑。共 **2 数据集 × 2 条件 × 3 线程 × 2 方式 × 2 复跑 = 48 个工作进程**。这些是性能样例，不是从正式四次调参中删除三次。

每个进程执行十个优化步骤，共 **480 个短训练步骤**：第 0 步单列为冷启动计算步，第 1–2 步为暖机，第 3–9 步为七个稳定步骤。模型和 Adam 构建另外计时，不隐入稳定步骤。不得事后删除慢步骤、移动暖机边界或增加重复次数。首次复跑按数据集、条件、线程 `[4,1,8]`、checkpoint 方式的固定顺序执行；第二次将完整的 24 项顺序反转，以缓和执行先后影响。

## 仅比较计算含义不变的执行方式

两种方式使用未修改的原 H2GCN、原 CPU COO 稀疏邻接、宽度 64、原 Adam、权重衰减 0.0005 和所选原 trial。禁止本轮改成 CSR、改变精度、修改模型、优化器或输入公式，或移到 CUDA。只向损失计算提供训练标签；无评分的全节点前向不索引验证或测试标签。

- `full_state_copy`：每次 snapshot 按原行为复制完整 `state_dict`，包括 `one_hop`、`two_hop` 两个静态邻接缓冲区。
- `static_adjacency_once`：每个工作进程只复制一次这两个只读静态缓冲区，各 snapshot 共享其只读引用；每次仍独立复制其他模型状态张量。还原时组合成完整的原 `state_dict`，验证一致性。

每个优化步骤完成后创建 **一份** snapshot，按 `step % 4` 替换四个保留槽之一；没有额外初始预填。第 3 步后四槽填满，第 4–9 步包含已有四槽时的替换与瞬时内存成本。两方式的槽调度完全相同。这模拟四次调参选定状态的保留压力，不按分数选 checkpoint，也不声称十步训练代替了完整四次调参。原 checkpoint 只包含模型状态；Adam 状态用于正确性审计，不改写原 checkpoint 含义。

静态缓冲区复制是重点核对对象，**不预先认定为根因**。若主要耗时来自邻接准备、稀疏运算、线程开销、记录或其他已测部分，应按实际报告。

## 分项计时与记录

单次开销分别计量：输入装载与绑定核验、特征变换、邻接准备、模型构建、Adam 构建、候选方式的一次静态邻接副本，以及初始静态哈希。

每个步骤分别记录：梯度清零、训练前向、训练损失、反向、优化器更新、无评分的评估模式前向、参数复制、静态缓冲区复制、正确性及哈希记录、JSON 序列化、独占写入和 fsync。同时直接测量完整步骤耗时及仅计算部分的小计。两方式必须执行相同任务量的审计与记录，不能让候选省略正确性工作而获得虚假提速；snapshot 的静态复制差异是本轮实际比较项。

另列 RNG 状态捕获、梯度/输出有限性检查和审计数组复制。完整模型状态的哈希扫描分成 `static_buffer_hash` 与 `dense_state_hash`，两者都是 `correctness_hash_instrumentation` 内的子项。初始 checkpoint 结构核验与静态边界核验分别记为 `initial_checkpoint_schema_validation`、`initial_static_boundary_validation`，并与一次静态副本和初始哈希一起作为 `checkpoint_store_setup` 内的子项。参数/静态复制同样属于 `checkpoint_total`。汇总时只加互不重叠的父项，不能把父项及这些子项重复相加。

**推荐依据使用包含记录开销的完整稳定步骤时间**。每个工作进程取七个稳定步骤的中位数，每个数据集/条件/线程/方式再取两次复跑中较慢的中位数。冷启动、暖机、一次性准备和最终审计成本单列；不得把它们漏报或称为零。额外给出仅计算耗时，区分训练计算与审计/写入成本。静态哈希和数据核验开销独立记录，不凭推测从计时中扣减。

轨迹完成后，另测 checkpoint 还原核验、跨线程数值证据保存及最终记录写入。若核验需要另建模型，安排在完整十步轨迹之后，避免构造模型消耗随机数并改变后续训练轨迹。所有输出带有性能诊断标识；数值审计张量不得续接为正式训练 checkpoint。

同时核对完整工作进程的计时账目：协调器实际观测的墙钟时间、已归属且不重叠的准备/步骤/最终审计总时间、工作进程内尚未归属的余量、最终记录写入，以及启动、导入、结束和协调器开销的剩余时间。差额据实报告，不把全部差额归因于某一已命名组件。

## 正确性、重复性与选择规则

所有输入绑定到既有完整数据哈希和原种子 0 切分；训练特征拟合仍使用既有公式。开启严格确定性，记录环境与线程设置，不启用 warning-only。CUDA 不可见且分配量要求为 0。

每个全新解释器在导入 Torch 前显式设置 `CUDA_VISIBLE_DEVICES=-1`，并在计量前及结束后检查没有可见 GPU、CUDA 未初始化。[PyTorch 2.9 官方环境变量说明](https://docs.pytorch.org/docs/2.9/cuda_environment_variables.html)明确将 `-1` 定义为不提供 GPU。启动合成测试发现 Windows 下空字符串未实现预期屏蔽，因此在任何研究计量之前改为该显式值；这是启动防护修复，不增加诊断轮次，也不改变 CPU 计算、样例或预算。

1. 同一线程数下，两种 checkpoint 方式的十步参数、梯度、Adam 状态、训练损失、训练前向输出及无评分评估输出轨迹必须逐位一致。
2. 相同设置的两个全新进程复跑必须逐位一致，包括各保留 checkpoint 的指纹。
3. 线程 1、8 分别与相同条件、方式、复跑的线程 4 比较。每步所有稠密参数、梯度、Adam 状态、训练损失、训练前向输出及无评分评估输出使用固定 `rtol=1e-5`、`atol=1e-6` 的逐元素检查；不要求这些浮点结果跨线程逐位相同，不因结果放宽容差。
4. 邻接静态状态在每步、两方式、各保留槽和还原后保持精确相同的哈希。还原后的完整状态及无评分输出与对应快照一致。全部数值须有限。

每个步骤前后的整数 RNG 状态在上述所有比较中均须**精确相同**，包括跨线程比较；不得对 RNG 数组使用浮点容差。

这些检查针对本次运行与样例中的计算含义，不是跨所有硬件和软件版本的数值证明。

以 **线程 4 + `full_state_copy`** 为固定参考，每个候选是统一用于四个数据集/条件样例的一个“线程数 + checkpoint 方式”组合。只在完整范围具备正确性、逐位复跑和资源通过证据时推荐。定义各样例速度比为“参考完整稳定步骤时间 / 候选完整稳定步骤时间”，取四个速度比的等权几何平均。候选必须同时满足：

- 几何平均速度比至少 **1.10**，即这一明确速度比定义下至少提高 10%。
- 任一样例的候选/参考时间比不超过 **1.10**，即没有样例慢超过 10%。
- 四个样例的全部正确性、重复性和资源条件均通过；不从结果中删除不利样例。

若多个候选满足，依次选择几何速度比最高、最大进程树内存最低、线程数较小、方式标识升序者。所有候选完整报告，不能按准确率选择。若有合格候选，明确推荐“采用已验证优化”，但结论限于所测范围，正式采用仍需后续固定全 11 数据集资源验收。若没有合格候选或本轮不完整，明确推荐“保留现有实现并修订预算”，同时披露失败或证据不足；不得把未完成解释成该优化在所有环境都无效。

## 本轮资源上限、失败与来源门槛

只运行这一轮固定设置：一个 CPU 工作进程，总累计运行时间上限 **7,200 秒**，单工作进程上限 **900 秒**，进程树常驻/峰值内存上限 **8 GiB**，系统可用内存至少 **4 GiB**，空闲磁盘至少 **20 GiB**。监测整棵所属工作进程树，包括 Windows 峰值，不能重复 v1 只监测启动器的问题。各尝试计入总预算；超限停止并保留记录。

新目录独占写入，保留所有失败、被中断任务和未完成范围；不自动重试或续跑。正确性或复跑失败须明确记录并拒绝该设置，不能静默删除。看到结果后不追加线程、实现、数据集、trial、步骤或重复次数。本轮结果后如需全 11 数据集验收，属于经方案审查的下一阶段，不偷偷扩展这一轮。

执行顺序固定为：针对不变式的测试通过 → 干净源码提交并推送 → 核对同一 SHA 的三个 CI 任务全部成功 → 保存 CI 凭据 → 执行本轮。命令必须提供 `--ci-receipt`；启动清单核对凭据中的提交与当前 HEAD 一致，将凭据哈希与源码、配置、资源参考及数据绑定哈希一并保存。测试至少覆盖槽独立性、静态只读共享、完整还原、RNG 不受审计扰动、计时边界、几何比与回退限制、超限终止、记录不可覆盖及评分计数始终为零。计算结束后，报告和记录同样先测试、提交推送、核对同 SHA CI 并保存证据。

## 推荐之后提交给用户的完整预算方案

本轮结束后必须给出上述二选一的明确执行建议，并基于实际证据提交完整预算方案，而不是继续无界优化。预算方案至少同时写明：

- **总累计运行上限**：包括所有工作进程及失败/恢复尝试；明确初始化、训练、checkpoint、记录和检查计入方式。
- **单模型四次调参上限**：覆盖全部四个原 trial、其原选择步骤及记录；不能仅列单 epoch 或单 trial 上限。
- **分批安排**：按固定数据集/种子/模型顺序组织可恢复批次，列出每批范围和最长运行限制，保留两条件配对。
- **停止规则**：资源、时间、数值、正确性、来源和记录异常如何停止；不得按准确率提前结束或改范围。
- **恢复规则**：保留失败记录，只跳过已完整核验的单位；恢复须绑定同一源码、配置、数据、环境与已批准预算，明确哪些变化要求新执行记录。

不得将两数据集的提速比例套到全部 11 数据集，也不得据此替换 v2 的 12.910 天整体估计。未完成新的全范围资源验收前，预算依据继续保留原全 11 数据集证据；样例级提速和一次性成本另列其局限，不伪装成全量预测。具体新预算数值在本轮实际结果后提出。

**完整预算方案须由用户确认。**本轮诊断授权不等于预算变更授权；在确认前不修改原预算、不打开正式开关。资源方案得到确认并通过相应验收后，再完成正式记录层、校验器与新记录分析适配层；这些门槛通过后才建立独立正式启动记录。本方案不把性能改善改写为准确率改善或全新独立确认性验证。
